📰 NOTICIAS DE LA SEMANA

Claude Haiku 5.5: $0.10/$0.50 por MTok, cache read $0.01, contexto 1M — 10x más barato que Haiku 4.5 en lista

Lanzado el 7 de octubre (claude-haiku-5-5). Pensado para clasificación, routing, extracción y subagentes: 1M de contexto, 128K de salida, adaptive thinking con effort (default medium), browser use tool y mínimo cacheable de 512 tokens (antes 4.096). Ojo: usa el tokenizer nuevo, así que el mismo texto cuenta ~30% más tokens que en Haiku 4.5 (el ahorro real ronda 7-8x, no 10x). Rompe cosas: temperature/top_p/top_k, prefill y budget_tokens devuelven 400, y el thinking viene activado por defecto. Es el candidato obvio para las rondas rápidas de JARVIS y las rutinas.

🔗 Claude Haiku 5.5 — overview y pricing · Qué hay de nuevo / breaking changes

Sonnet 5.5: cache reads a la mitad ($0.20 → $0.10/MTok) y créditos de API incluidos en Max y Team

El 7 de octubre Anthropic bajó el cache read de Sonnet 5.5 a 0.05x el precio base de input (antes 0.1x); cache writes y resto de precios sin cambios. Además, los planes Max y Team incluyen ahora créditos mensuales de API para apps y agentes en Claude Platform. Es exactamente el modelo de conversación de JARVIS y de tus rutinas: con system prompt largo cacheado, el coste del input repetido se reduce a la mitad sin tocar código.

🔗 Claude Platform — release notes (7 oct)

Managed Agents: 'dynamic workflows' en beta — el agente escribe un workflow que lanza muchos agentes por fases

El 9 de octubre Anthropic añadió, en beta (managed-agents-2026-04-01), la capacidad de que un agente escriba un programa que ejecuta muchos agentes en fases y combina sus resultados (p. ej. revisar cientos de documentos). Corre en servidor como workflow run y se sigue con eventos workflow_run.*. Se activa con multiagent: {type: "multiagent_20261001", workflows: {type: "enabled"}}. Para ti: referencia directa de diseño para Mission Control (orquestación por fases con agregación) y alternativa a montar la orquestación a mano.

🛠️ HERRAMIENTA DE LA SEMANA

OpenAI Decisions API (beta pública sobre GPT-6 Luna) · letsdatascience — beta pública · Beta abierta a todos los desarrolladores desde el 6-oct

Qué hace: Endpoint POST /v1/decisions que devuelve respuestas tipadas por pregunta: predicate (probabilidad de que algo sea verdad), choice (una opción de un conjunto fijo) y score (media ponderada por probabilidad). Solo gpt-6-luna por ahora, imágenes en base64. Precio: $0.10/MTok de input; cache y output sin cargo. OpenAI dice ~10x más rápido que Responses (sin benchmark independiente). Incluye ZDR, HIPAA y residencia de datos en EEUU/Europa.

Para quién es útil: La clasificación de emails importantes y el routing de intenciones de JARVIS, sin parsear JSON ni gastar tokens de salida. Contra-argumento: Haiku 5.5 con salida estructurada hace lo mismo dentro de Anthropic, a $0.10/$0.50; prueba ambos con 50 emails reales.

Tutorial en 3 pasos:

  • Pide acceso a la beta con tu API key de OpenAI y lee la referencia de /v1/decisions.
  • Define 3-5 preguntas por email: choice para categoría (escuela / dinero / seguridad / persona / ruido) y predicate para '¿requiere respuesta hoy?'.
  • Mide latencia p50/p95 y acierto frente a tu clasificador actual con 50 emails etiquetados; si el hueco es pequeño, quédate en Claude.

💡 CONCEPTO DE LA SEMANA

Deriva del tokenizer: por qué el precio por token ya no es comparable entre versiones

Un tokenizer nuevo cambia cuántos tokens produce el mismo texto: Haiku 5.5 usa el de Claude 4.7+ y cuenta ~30% más tokens que Haiku 4.5. Con $0.10 vs $1.00 de input, el ahorro de lista del 10x es en la práctica ~7.7x, y los thinking blocks de turnos anteriores (que Haiku 5.5 conserva y cobra como input) lo reducen más en conversaciones largas. Compara siempre coste por tarea con tus prompts reales, no $/MTok; es la métrica que importa para presupuestar rutinas.
